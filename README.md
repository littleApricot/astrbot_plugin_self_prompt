# 记忆与记事本

AstrBot 的常驻资料与可维护记事本。采用下面五个常驻分区。

| 分区 | 用途 | 修改方式 |
| --- | --- | --- |
| 性格和人设 | 身份、性格与人设要求 | 用户手动修改 |
| 回复偏好 | 输出风格、格式及表达要求 | 用户手动修改 |
| 聊天示例 | 具体聊天情境与期望回复，示范语气、接话及表情包和语音的使用 | 用户手动修改 |
| 昵称 | 机器人和成员的昵称、别名及称呼对应关系，按列表保存 | 用户逐项编辑，机器人通过 nickname_update 增删 |
| 自我认知 | 相处中形成的认识、习惯和需要记住的变化 | 用户手动修改，机器人通过 self_memory_update 维护 |

五个分区每轮完整加载。self_memory_update 的保存权限由程序限定为“自我认知”；昵称工具只能写昵称列表。聊天示例与人设、回复偏好同属用户维护的部分，两个模型工具均不能修改。记事本保存黑话、详细事件、关系、待办和流程，每轮只加载全部页面目录，正文由机器人按需读取。

同一人格的群聊和私聊共享常驻资料及记事本。涉及个人事实时，写明对应成员与必要的适用会话。

## 安装和更新

适配 AstrBot 4.29.1。仓库沿用 [astrbot_plugin_self_prompt](https://github.com/littleApricot/astrbot_plugin_self_prompt)，共享源沿用 [littleApricot AstrBot 插件源](https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json)。

已发布版本可以通过插件页检查更新，或从 [GitHub Releases](https://github.com/littleApricot/astrbot_plugin_self_prompt/releases/latest) 下载 ZIP 安装。数据位于插件数据目录与 AstrBot 人格数据库，更新程序文件保留数据。

回复模型需要支持工具调用；采用工具白名单的人格需加入下文列出的记事本工具、nickname_update、self_memory_update 和 get_self_prompt。

## 用户管理页

在插件详情中打开“记忆与记事本”视图，复用 AstrBot 登录认证：

| 区域 | 操作 |
| --- | --- |
| 当前记忆 | 编辑性格和人设、回复偏好、聊天示例、昵称列表、自我认知；查看字节占用与连续未维护轮次 |
| 记事本 | 查看完整目录，新建、读取、修改和删除页面 |
| 记忆记录 | 查看当次完整资料、结果和实际原文来源；恢复选中的内容 |
| 配置 | 设置维护提醒间隔、页数上限和高级预算 |

昵称每项保存一个昵称或称呼对应关系，例如“机器人：阿蓝”“成员甲：小甲”。点“添加昵称”，编辑或删除对应行后点“保存记忆”；空行略过，相同条目去重。“自我认知”也可以直接编辑。

“聊天示例”位于回复偏好下面，可以粘贴多段对话示例及其必要背景，用同一个文本框编辑。示例随人设常驻提供给模型，保存时进入记忆快照；初始为空，由用户填写。

原“人格设定 → 当前人格 → 编辑 → 系统提示词”入口仍可修改常驻资料。正常保存会留下独立记录；手动编辑正文时保留已有分区定位标记。管理页保存保留外部附注。

恢复记录默认只恢复昵称与自我认知，保留当前人设、回复偏好和聊天示例；用户可以勾选同时恢复记录中的这三部分。勾选后恢复没有聊天示例的旧记录，会将聊天示例恢复为空。

## 上下文和记事本

五个常驻分区与完整记事本目录通过 astrbot_plugin_self_prompt 来源进入系统块，直接显示各分区标题。与 LCM 配合时，每次模型调用读取最新目录；工具新增、删除页面或修改标题和描述后，下一步请求即可看到变化，后续历史不重复保存。单独使用时，目录在每轮回复请求开始时放入系统提示词。

回复判断 v0.8.3 起接收完整常驻资料、近期聊天和当前时间，不接收本轮目录、维护提醒或工具定义。历史里正常保留的工具调用、返回和已读正文仍按判断预算参与。配套回复判断 v0.9.1 与 LCM 时，正式回复使用所属批次的完整有效窗口。

配套 LCM v0.6.9 与工具说明编辑 v0.3.1 时，完整工具用法与参数说明统一进入系统提示词；调用接口保留参数结构和约束。独立使用时仍沿用 AstrBot 的工具定义。机器人根据目录选择页面，调用 notebook_read 读取正文；记录新事实、约定或流程时优先修改相关页，再考虑新建。

每页名称最多 24 个字符，描述最多 60 个字符，正文最多 12,000 个字符；每次最多读取 4,000 个字符，长页继续分页。目录完整展示，页数与目录字节预算同时约束新增内容。

修改和删除前先读取页面，替换正文前读完全文。页面变化时重新读取再合并；插件在当前任务内核对读取状态。满页时仍能读写、删除已有页面；降低页数上限保留现有页面，直到有空位再允许新增。

目录不反复写入历史，工具调用及返回仍沿 AstrBot 正常流程保存。已读正文随聊天窗口和压缩机制管理，页数上限不代表整个上下文大小固定。

## 主动维护与临时提醒

机器人可以随时根据聊天中值得保留的变化调用 nickname_update 或 self_memory_update。昵称保存称呼对应关系，自我认知保存相处中形成的认识与习惯；内容遵循用户维护的人设、回复偏好与聊天示例。黑话、详细事件和流程放在记事本。

默认每个会话、人格组合连续 100 轮未发生模型维护时，在第 100 轮正式回复前加入一次临时提醒：

> 你已经很久没有更新昵称和自我认知了。看看最近的消息，有没有值得更新的内容；如果有，先更新再回复，没有就正常回复。

计数规则：

- 机器人通过回复判断、进入正式回复流程算一轮；一批合并消息回复只算一轮。
- 判断后沉默的消息不计数；同一轮的工具往返、流式片段和重试不额外计数，重复消息标识去重。
- 加入提醒时立即清零，无论模型随后修改或正常回复，下一轮重新累计。
- 昵称或自我认知通过模型工具成功保存实际变化时清零；同一人格共享资料，该人格各会话的计数一起清零。失败或无变化的工具调用不清零。
- 关闭提醒后暂停计数，重新开启继续累计；计数和已处理消息标识保存在本地，重启后保留。

提醒只进入本轮临时区。与 LCM 配合时随临时声明提供，单独使用时标为临时内容；回复判断和持久历史不包含这条提醒。模型依据当前可见聊天决定是否修改；提醒本身只由本地计数产生。

成功修改会保存完整记忆快照及操作类型。管理页提供昵称维护、自我认知维护和手动编辑记录，旧版整理记录及其原文来源继续可查。保存先留下备份和待提交记录，再调用 AstrBot 人格管理器写入并回读；中断后根据原文与目标内容恢复，受工具分区权限约束。

## 配置

| 配置键 | 默认值 | 含义 |
| --- | --- | --- |
| memory_reminder_enabled | true | 启用按正式回复轮次累计的维护提醒 |
| memory_reminder_interval | 100 | 连续多少轮未修改时提醒一次，正整数 |
| notebook_max_pages | 100 | 每个人格当前记事本页数上限，正整数 |
| long_term_memory_max_bytes | 8000 | 昵称与自我认知内容的 UTF-8 字节上限 |
| notebook_catalog_max_bytes | 20000 | 完整目录 UTF-8 字节上限，含标识及结构 |

人设、回复偏好和聊天示例不计入昵称与自我认知的可维护内容预算，仍计入模型总输入。已有超额内容完整保留；两个维护工具产生的变化需满足预算；用户仍可手动编辑已有超额内容。

管理页分别显示正式回复常驻资料与判断常驻资料。判断优先保留完整常驻资料，剩余空间还需容纳判断指令、请求封装和近期消息；本轮目录只占正式回复的常驻资料。目录预算不能降到小于已有目录大小。

## 工具参考

所有工具绑定当前请求实际选中的人格，不接受跨人格参数。

| 工具 | 必填参数 | 可选参数 | 成功结果 |
| --- | --- | --- | --- |
| get_self_prompt | 无 | 无 | ok、sections；sections 含 persona、output_preferences、chat_examples、other 字符串和 nicknames 字符串列表；other 是自我认知的兼容字段名 |
| nickname_update | 无 | add、remove，至少一个含条目 | ok、更新后的 nicknames 完整列表 |
| self_memory_update | content：自我认知的完整新正文 | 无 | ok、self_knowledge、changed |
| notebook_read | page_id | offset=0、limit=4000 | 名称、描述、正文片段及分页信息 |
| notebook_create | title、description、content | 无 | 页面标识、名称、描述、剩余容量 |
| notebook_update | page_id | title、description、content，至少提供一个 | 当前页面标识、名称、描述和容量 |
| notebook_delete | page_id | 无 | 删除结果、页数和剩余容量 |

nickname_update 的 add、remove 都是字符串列表，省略表示不操作；删除按完整条目匹配，改名可以同时删除旧项、添加新项，两者不能包含同一条目。首尾空白和重复项会去除；重复添加或删除不存在的条目保持原状。保存层限制只改昵称，对最新列表应用增删，连续冲突返回 content_changed。成功修改记录为“昵称维护”。

self_memory_update 的 content 是更新后的完整自我认知正文，空字符串可清空此部分。工具基于本轮已提供的内容，或 get_self_prompt 最近返回的内容检查并发变化；不一致时返回 content_changed，先读取再合并。成功返回 self_knowledge 和 changed，实际改变才清零维护计数。保存层限制只改自我认知，插入分区标记返回 invalid_section_content；超过预算返回 memory_budget_exceeded。

notebook_read 的 offset 按字符计算，limit 范围为 1 到 4000。返回 ok、page_id、title、description、content、offset、total_chars、next_offset 和 has_more；继续读取使用 next_offset。

创建的名称、描述和正文都必须非空，并符合长度限制。更新时省略的字段保留原值；提供 content 表示完整新正文，空正文会被拒绝。修改、删除前读取当前页，替换正文前分段读完；内容已变化时重新读取再合并。

失败统一返回 ok=false、error、message。昵称错误包括 invalid_nicknames、nickname_action_required、content_changed、memory_budget_exceeded；记事本错误包括 page_not_found、page_changed、read_page_first、notebook_full、catalog_budget_exceeded、invalid_page_content。

## 升级迁移与数据位置

v0.8.0 为现有分区补上空的“聊天示例”，已有正文保留，不自动从人设中抽取或填入示例。升级前已经打开的旧管理页保存时，省略 chat_examples 字段会保留已存的示例；新版管理页可以正常填写或清空。

升级前备份完整人格原文。旧固定设定内容按原文合入“性格和人设”，原人设、回复偏好保留；旧常驻 memory 内容保留在“自我认知”。原“其他”标题改为“自我认知”，正文、内部 other 字段及定位标记保留。已有昵称列表沿用，旧昵称文本按非空行转换并去重。迁移不调用模型重新分类，外部附注保留，重复启动不重复合并。

已存入记事本的内容和原文来源继续保留。混在旧人设正文或笔记里的称呼保留原文，可以由用户整理，或由机器人通过昵称工具维护。

从旧版自动整理升级时，旧队列、整理记录和来源作为历史资料保留，首次启用轮次提醒从零开始。后续升级保留已有轮次计数。旧自动整理的待提交结果若尚未写入，则标为结束使用；已成功写入的结果保留。昵称与自我认知工具的待提交保存继续受分区权限约束。原始备份可在记录中查看，时间标明导入时间；旧版缺失的聊天依据不伪造。

主要数据位于 data/plugin_data/astrbot_plugin_self_prompt/：

| 位置 | 内容 |
| --- | --- |
| auto_memory.sqlite3 | 当前页面、维护计数、去重标识、记忆记录及旧队列和来源 |
| backups/ | 人格完整原文备份 |
| upgrade_v0_4_backup/ | 旧版升级前的队列、配置及备份 |

原文来源默认留存，记事本页数上限不限制这些资料的磁盘用量。与 LCM 配合时，旧工具管理字段在有效历史副本中隐藏，原文留在完整档案；独立运行时另存于本插件数据库，工具调用关系和业务正文保留。

v0.8.0 新增聊天示例编辑、旧布局兼容和用户写入权限，按用户要求未运行功能测试或模型调用。代码与文档已审查；发布校验仅覆盖版本、安装包及原插件源信息，不代表功能验证。

v0.7.0 的主动维护、轮次提醒和标题迁移按用户要求未运行功能测试。发布校验仅覆盖版本、安装包和原插件源校验值；此前版本的验证结果不代表本次功能改动已通过。
