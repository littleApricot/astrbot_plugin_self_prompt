# 自维护提示词

让 AstrBot 通过工具维护当前人格提示词，暂时作为可编辑的长期记忆。提示词分为三个部分：

| 部分 | 内容 |
| --- | --- |
| 性格和人设（包括昵称） | 身份、性格、昵称、称呼等设定 |
| 输出偏好要求 | 语言、长短、语气、格式等长期偏好 |
| 其他需要记住的事情 | 值得跨轮次保留的事实、约定和信息 |

修改直接保存到 AstrBot 的人格数据库，下一次正式回复请求自动加载；也会出现在原有的人格设定页面。共用同一人格的群聊和私聊共享这些内容，不按群另建一份记忆。调用工具的本轮会看到修改结果，新提示词从下一次请求开始注入。

## 安装与使用

适配 AstrBot 4.29.1。与“回复判断”“群聊表情图库”共用同一个插件源。已添加该源时，刷新列表后找到“自维护提示词”并安装；首次使用时添加以下地址：

```text
https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json
```

也可以在插件页通过仓库地址安装：

```text
https://github.com/littleApricot/astrbot_plugin_self_prompt
```

手动安装可下载 [GitHub Releases 中的 ZIP](https://github.com/littleApricot/astrbot_plugin_self_prompt/releases/latest)，在插件页上传。安装后启用“自维护提示词”。插件提供 `get_self_prompt` 和 `update_self_prompt` 两个工具，无需填写新的 API Key。

通过插件源安装后，后续发布会出现在插件页的更新检查中，点击更新即可。通过仓库地址安装则从该仓库更新。ZIP 安装的插件需在插件详情中绑定上述插件源，才能使用一键更新。更新程序文件保留人格数据库和插件备份数据。

机器人继续使用已有回复模型，需要该模型支持工具调用。当前人格使用全部工具时会自动获得这两个工具；若在人格页面配置了工具白名单，将这两个名字加入白名单。

可以在对话里告诉机器人“以后回答简短一点，请记住”，或者纠正需要长期保存的事实。插件会在每次请求里说明三个分区和读写方法，由回复模型判断是否调用工具；仅口头回答“记住了”不能证明已保存，以成功的工具返回值为准。

## 每 100 条消息自动整理

默认开启。每个会话、每个人格分别累计：一条用户消息算一条，一次模型完成的最终回复算一条。机器人没有回复的用户消息也计数；工具调用、中间输出和流式片段不单独计数。文字和媒体消息都可计数，图片、语音等在整理输入中以占位文字表示，不重新识别媒体内容。

启用后从新收到的消息开始累计，不回放升级前的旧历史。例如 50 条用户消息加 50 次机器人最终回复达到 100 条，会触发一次；机器人一直沉默时，则在收到第 100 条用户消息后触发。各群聊和私聊的数量分别计算，不把多个会话凑成一批。

满 100 条时，插件在后台使用来源会话的回复模型，读取这批消息和当前三个分区，整理值得保留的信息。它可以补充、合并、去重和纠正三个分区；人设、昵称和输出偏好只根据明确约定或纠正修改，个人信息保留所属会话和用户标识。没有新信息时保持原提示词不变，这批消息仍记为已整理。共用同一人格的会话继续共享整理后的内容。

整理结果写入同一份人格提示词，在“人格设定 → 当前人格 → 编辑 → 系统提示词”中可以查看和手动修改，下一次回复请求自动加载。整理过程中若你或另一个工具修改了提示词，后台放弃这次旧结果，保留消息等待重试。

累计进度和待整理消息保存在插件数据目录，重启或升级后继续累计。每次成功处理最早的 100 条，其间新到的消息留给下一批；大批积压按每 100 条继续处理。模型报错、超时或返回格式无效时不推进进度，等待后续消息触发重试，两次失败尝试至少间隔 60 秒。

整理通过独立模型调用完成，不发送群聊消息，也不改 AstrBot 原有聊天历史。通常每 100 条需要一次额外模型调用；输入过长时会分段处理并在全部成功后统一保存，完整保留先后消息，不通过删除旧消息来缩短输入。

| 插件配置 | 默认值 | 含义 |
| --- | --- | --- |
| 每累计 100 条聊天消息自动整理记忆 | 开启 | 关闭后暂停收集和自动整理，手动读写工具仍可使用 |
| 每次记忆整理模型调用超时秒数 | 60 | 单次整理调用的等待上限 |

后台整理由这个开关控制，对话中的直接读写由工具权限控制，两者分别生效。

初次安装和读取工具都保留原人格文本。首次修改时创建三个分区；没有修改“性格和人设”时，原文本完整归入该分区。之后只替换指定分区，其他分区及文档周围的内容保留。提示词中的管理标记用于定位分区，在人格页面手工编辑时应保留它们。

## 工具参考

`get_self_prompt` 无模型入参，返回 `ok`、当前 `persona_id`、完整提示词内容对应的 `revision`，以及三个分区组成的 `sections`。没有可编辑人格或文档标记损坏时返回错误。

`update_self_prompt` 参数：

| 参数 | 必填 | 含义 |
| --- | --- | --- |
| `section` | 是 | `persona`、`output_preferences` 或 `memory` |
| `content` | 是 | 指定部分修改后的完整内容；空字符串清空这一部分 |
| `expected_revision` | 是 | 最近一次读取工具返回的 `revision` |

成功时返回 `ok: true`、新 `revision`、更新后的 `sections` 和 `effective: next_request`。`revision_conflict` 表示读取后内容已被其他编辑改变，模型应重新读取、合并后再提交。工具绑定本轮实际选择的人格，模型不能通过参数指定另一个人格。

工具遵循 AstrBot 的插件工具权限设置。默认情况下普通成员的对话也可能促使模型修改当前人格；如需限制修改，在工具管理中设置 `update_self_prompt` 的权限。

## 保存与备份

每次修改前，将原始提示词备份到 `data/plugin_data/astrbot_plugin_self_prompt/backups/`。备份以人格 ID 的摘要分目录，文件名是原提示词的内容摘要。日志只记录修改的分区名称和错误类型。

自动整理的待处理消息、去重标识和进度保存在同目录的 `auto_memory.sqlite3`。处理成功后清除这批消息的正文，并保留最近处理过的消息标识用于去重。自动整理日志只记录条数、是否修改和错误类型，不打印聊天原文、完整提示词或模型响应。

人格原有的工具白名单、技能设置、开场白和错误提示设置继续由 AstrBot 管理。插件更新保留数据库里的提示词及插件数据目录中的备份。

## 验证范围

在本插件目录运行：

```bash
ASTRBOT_SOURCE=/path/to/AstrBot
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH="$ASTRBOT_SOURCE:$PWD/.." \
  ASTRBOT_ROOT=/tmp/astrbot-self-prompt-test \
  "$ASTRBOT_SOURCE/.venv/bin/python" -m pytest tests -q
```

测试使用隔离 SQLite 数据库、记录输入的测试模型和 AstrBot 原有的人格管理、请求组装代码，检查三个部分的修改、并发版本冲突、重建人格管理器后的持久化、下一轮提示词加载、人格作用范围和原有工具配置保留。自动整理覆盖第 99/100 条的触发边界、沉默消息、最终回复及媒体消息计数、去重、重启恢复、会话与人格隔离、失败重试、手动修改冲突，以及长消息完整分段。不调用真实模型或向 QQ 发消息。

## 发布更新

发布新版本时，同时修改本仓库 `metadata.yaml` 的 `version`、`plugins.json` 中的两个版本号及 `download_url` 的版本标签。提交后创建同名 Git 标签并推送到 GitHub，再发布对应 Release。

将更新后的插件条目同步到 `littleApricot/astrbot_plugin_reply_gate` 仓库的共享 `plugins.json`，保留其他插件条目；在共享源仓库运行 `python scripts/prepare_release.py`，生成匹配的 `plugins-md5.json`，将列表和校验文件一起提交发布。用户继续使用共享源地址安装和更新。下载地址固定到版本标签，避免版本信息与代码不一致。
