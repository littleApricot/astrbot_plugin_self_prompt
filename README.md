# 记忆与记事本

AstrBot 的常驻记忆与可维护记事本。常驻记忆每轮加载，日常聊天只读；机器人通过记事本工具保存事实、约定、待办和流程，每轮只加载页面目录，需要正文时主动读取。

| 内容 | 加载方式 | 修改方式 |
| --- | --- | --- |
| 用户固定设定 | 每轮完整加载 | 用户手动修改 |
| 性格和人设、回复偏好、昵称 | 每轮完整加载 | 用户手动修改，后台按消息数整理 |
| 记事本：黑话、关系、事实、约定和流程 | 每轮加载全部页面名称和描述，正文按需读取 | 用户编辑，机器人主动通过工具维护 |
| 记忆记录与原文来源 | 用户打开管理页时读取 | 插件自动留存 |

同一人格的群聊和私聊共享常驻记忆与记事本。涉及个人事实时，应在页面里写明对应成员与适用会话。

## 安装和更新

适配 AstrBot 4.29.1。沿用原“自维护提示词”插件的仓库和共享插件源；更新后显示为“记忆与记事本”。

共享源：[littleApricot AstrBot 插件源](https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json)。

仓库：[astrbot_plugin_self_prompt](https://github.com/littleApricot/astrbot_plugin_self_prompt)。

通过已有插件页检查更新，或从 [GitHub Releases](https://github.com/littleApricot/astrbot_plugin_self_prompt/releases/latest) 下载 ZIP 安装。原始数据保存在插件数据目录和 AstrBot 人格数据库，更新程序文件保留这些数据。

插件继续使用来源会话的回复模型进行后台整理，无需另填 API Key。回复模型需要支持工具调用；采用工具白名单的人格需要加入下文列出的记事本工具和只读 get_self_prompt。

## 用户管理页

在 AstrBot 插件页打开插件详情，进入“记忆与记事本”视图。页面复用 AstrBot 的登录认证，包含四个区域：

| 区域 | 操作 |
| --- | --- |
| 当前记忆 | 编辑固定设定、性格和人设、回复偏好、昵称；查看字节占用与整理进度 |
| 记事本 | 查看完整目录，新建、读取、修改、删除当前页面 |
| 记忆记录 | 查看每次的记忆全文、结果与本次原文来源；恢复选中的记忆内容 |
| 配置 | 设置整理频率、页数上限和高级预算 |

原“人格设定 → 当前人格 → 编辑 → 系统提示词”入口仍然可以修改常驻内容，正常保存也会留下一条记忆记录。管理页编辑时保留原有外部附注；原人格页面手动编辑正文时，保留已有的分区定位标记。

记忆记录由用户管理界面查看。日常回复、回复判断和后台整理的模型接口只获得当前任务资料，管理编号、记录查询和恢复信息留在插件内部。

## 记事本怎样使用

与 LCM v0.6.1 配合时，固定设定和三个常驻分区按 `astrbot_plugin_self_prompt` 来源进入系统块，直接显示“性格和人设、回复偏好、昵称”三个标题。完整记事本目录放在本轮临时块，每次模型调用读取最新目录，后续历史不重复保存。单独使用时，目录随本轮请求动态生成，提供给正式回复模型。回复判断 v0.8.3 读取完整常驻记忆、近期聊天及当前时间，不接收本轮目录；已正常保存在历史里的读页结果仍按判断预算参与。正式回复使用最新有效历史。

记事本的使用条件和读写规则放在各工具的描述中，随工具定义提供给正式回复模型。回复判断不接收本轮工具定义。管理页的“常驻资料”按 UTF-8 字节统计人设、长期记忆和目录；工具描述单独随回复请求提供。

机器人根据目录选择页面，调用 notebook_read 读取正文。遇到值得以后使用的事实、约定、待办或 SOP 时，提示它优先修改已有相关页面，再考虑新建。保存是否成功以工具返回为准。

每页名称最多 24 个字符，描述最多 60 个字符，正文最多 12,000 个字符；每次最多读取 4,000 个字符，长页继续分页。目录必须完整展示，页数和目录字节预算同时限制新增内容。

满页时仍可修改、删除已有页面；新建会返回容量不足。降低页数上限保留已有页面，直到有空位再允许新建。修改覆盖当前内容，删除移除页面并释放容量。

修改和删除前先读取当前页面。插件在当前处理任务内检查读到的内容是否仍然有效；出现“内容已变化”时重新读取后再合并。全文替换前需要读完整页，避免漏掉后半部分。

工具调用、返回和已读正文仍按 AstrBot 原流程保留在聊天历史中；目录本身不会每轮重复写进历史。页数上限约束常驻目录，已经读取的正文仍受正常聊天窗口与压缩机制管理。

## 自动整理和原文来源

默认每累计 100 条新消息整理一次，可以修改频率。各会话与人格组合分别累计：

- 一条用户消息算一条，机器人保持沉默也计数。
- 一次模型最终回复算一条；工具调用、流式片段和中间输出不另计。
- 连续消息合并回复时仍按原始用户消息分别计数。
- 使用消息标识去重，重投不重复累计。

50 条用户消息加 50 次最终回复即可达到 100 条，100 条用户消息没有回复也能达到。关闭自动整理时暂停采集和开始新任务，保留已有队列；重新开启后继续累计，关闭期间未采集的消息不补算。

后台任务整理性格和人设、回复偏好、昵称三个分区，用户固定设定保持原样。明确约定、含义清楚的稳定用法和纠正才适合成为常驻内容；临时玩笑、推测和机器人自述不能直接当成用户确认的事实。昵称注明对应对象和必要的适用会话。黑话含义、成员关系、具体事实、待办和流程通过记事本维护。

整理来源包括本批新聊天和当前记事本。首次整理读取现有页面，之后读取新增或改动的页面；页面的读取进度只在记忆保存成功时确认，无变化的成功整理也确认进度，失败后继续保留待处理来源。页面在整理期间又被修改时，下次仍会读取新内容。记事本不计入消息频率，仍由配置的聊天消息数触发整理。

记事本中的人设、回复偏好和昵称线索经判断后合并进对应常驻分区；旧笔记中的猜测不当成明确约定。实际读取的页面名称、描述和正文快照随本次记忆记录保存，在来源列表中以“记事本《页面名称》”显示；页面以后修改或删除，仍能查看当次依据。模型输入只含页面资料，内部读取进度不对模型展示。

每次成功整理保存：

- 当次完整的固定设定和长期记忆正文。
- 结果“已更新”或“无变化”。
- 这一轮实际读过的原文，包括发送人、昵称、来源会话、时间、文本和可取得的消息结构。

无变化也独立保存本次来源。管理页会显示结果，页面打开时定期检查新结果并提醒；后台日志以中文显示“已更新”或“无变化”。提醒面向用户管理侧，不作为群消息发送。

图片等媒体按现有文字占位形式参与整理，消息结构与媒体引用可在来源中查看；占位符不代表整理模型已经识别图片。原文独立保存在插件数据库，将旧聊天移出上下文后仍可查看。

模型报错、超时、输出不合法或保存冲突时保留待处理消息，不推进批次；失败记录与“无变化”分开显示。成功后继续处理积压批次。原文、完成进度和记忆记录在同一插件数据库确认，跨人格数据库写入使用可恢复的待提交状态。

手动修改的来源显示为用户编辑，没有聊天来源时如实留空。恢复历史记忆会形成一条新的用户操作记录；用户可以选择是否同时恢复固定设定。

## 配置

| 配置键 | 默认值 | 含义 |
| --- | --- | --- |
| auto_memory_enabled | true | 采集消息并运行后台整理；关闭后保留已有资料 |
| auto_memory_message_interval | 100 | 每累计多少条新消息整理一次，正整数 |
| notebook_max_pages | 100 | 每个人格的当前页面上限，正整数 |
| auto_memory_timeout | 60 | 单次整理调用超时秒数 |
| long_term_memory_max_bytes | 8000 | 可整理长期记忆的 UTF-8 字节上限，不含用户固定设定 |
| notebook_catalog_max_bytes | 20000 | 完整目录的 UTF-8 字节上限，含名称、描述、标识和结构 |

这些预算是字节数，消息频率是条数。它们与回复判断插件的总输入预算分别生效。

管理页分别显示正式回复常驻资料和判断常驻记忆。判断优先保留完整固定设定和长期记忆，剩余预算还需容纳判断指令、请求封装和近期消息；本轮目录只占正式回复的常驻资料。插件不会用判断裁剪结果缩短正式回复窗口。

目录预算不能通过管理页降到小于已有目录的大小。用户手动写入的超额长期记忆保留原文；自动产生的新内容需要符合预算，无变化的整理仍可留记录。

## 工具参考

所有工具绑定当前请求实际选中的人格，不接受跨人格参数。模型只接触当前记忆和当前页面内容。

| 工具 | 必填参数 | 可选参数 | 成功结果 |
| --- | --- | --- | --- |
| get_self_prompt | 无 | 无 | ok、fixed_prompt、sections；sections 含 persona、output_preferences、nicknames |
| notebook_read | page_id | offset=0、limit=4000 | 页面名称、描述、正文片段及分页信息 |
| notebook_create | title、description、content | 无 | 页面标识、名称、描述、剩余容量 |
| notebook_update | page_id | title、description、content，至少提供一个 | 当前页面标识、名称、描述和容量 |
| notebook_delete | page_id | 无 | 删除结果、当前页数和剩余容量 |

读取的 offset 按字符计算，limit 范围为 1 到 4000。返回字段为 ok、page_id、title、description、content、offset、total_chars、next_offset 和 has_more；继续读取使用 next_offset。

创建的名称、描述和正文都必须非空，并符合前述长度边界。更新时省略的字段保留原值，提供的 content 表示更新后的完整正文；传空正文会被拒绝。

失败返回 ok=false、error 和 message。常见错误包括 page_not_found、page_changed、read_page_first、notebook_full、catalog_budget_exceeded 和 invalid_page_content。后台整理写入走内部路径，原 update_self_prompt 已从模型工具中撤下。

## 升级迁移和数据位置

升级时先备份旧人格原文，再将原 persona 和 output_preferences 保留为常驻记忆，将原 memory 全文顺序移入“迁移记忆”页面。超过单页长度时拆页，全部写入成功后才移出原常驻提示词。迁移不调用模型重新分类，容量不足时保留原文等待处理。

新版新增独立的 nicknames 分区，旧人设正文先保留。下一次按消息数触发整理时，模型可整理昵称，并提交旧分区中的黑话原文片段。程序逐字校验片段，先写入“群聊黑话”记事本页面，再移出原分区；同一次整理不能改写正在迁移的分区，其余原文保持。容量不足或保存失败时保留旧内容和待整理消息；中断后的保存可恢复，成功后才确认消息进度。

原始固定区、外部附注和其他人格配置保留；已有待整理队列继续使用。旧版已经清空的原文不会伪造成可追溯来源。可识别的旧提示词备份可在记忆记录中查看，记录时间为导入时间。

主要数据位于 data/plugin_data/astrbot_plugin_self_prompt/：

| 位置 | 内容 |
| --- | --- |
| auto_memory.sqlite3 | 当前记事本、消息队列、记忆记录及其原文来源 |
| backups/ | 人格原文备份 |
| upgrade_v0_4_backup/ | 旧版升级前的队列数据库、插件配置和已有原文备份 |

原文来源默认留存，记事本页数上限不限制这些资料的磁盘用量。与 LCM 配合时，旧工具管理字段只在有效历史副本中隐藏，原文在 LCM 完整档案中保留；独立运行时另存到本插件数据库。业务正文与工具调用关系继续保留。

## 验证

确定性检查使用 AstrBot 原生人格管理器、SQLite、ProviderRequest 和插件扩展 API 分发，覆盖迁移、计数、只读边界、保存恢复、来源关联、无变化、并发容量和工具输出。

~~~bash
export ASTRBOT_SOURCE=/path/to/AstrBot
export PYTHONPATH="$ASTRBOT_SOURCE:$PWD/.."
export ASTRBOT_ROOT="$(mktemp -d)"
PYTHONDONTWRITEBYTECODE=1 "$ASTRBOT_SOURCE/.venv/bin/python" -m pytest tests -q
~~~

管理页检查使用隔离测试实例和无界面浏览器，实际操作保存、读写删除、配置、来源查看与记忆恢复。真实人格的迁移验证只读取原数据，在私有临时副本中执行。

自动化整理测试使用受控模型输出验证输入、校验和保存流程；尚未调用真实模型验证主动记事及语义整理质量，也未向 QQ 发送测试消息。实际使用时，模型是否恰当记录和读取仍需要观察。

完整设计和验收依据见 [升级计划](docs/memory-notebook-plan.md)。
