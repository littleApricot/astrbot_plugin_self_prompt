# 记忆与记事本

AstrBot 的常驻资料与可维护记事本。v0.6.0 采用下面四个常驻分区。

| 分区 | 用途 | 修改方式 |
| --- | --- | --- |
| 性格和人设 | 身份、性格与人设要求 | 用户手动修改 |
| 回复偏好 | 输出风格、格式及表达要求 | 用户手动修改 |
| 昵称 | 机器人和成员的昵称、别名及称呼对应关系，按列表保存 | 用户逐项编辑，机器人通过 nickname_update 增删 |
| 其他 | 自动总结得到的简短事实、约定和提醒 | 用户手动修改，后台按消息数自动整理 |

四个分区每轮完整加载。自动总结的保存权限由程序限定为“其他”；昵称工具只能写昵称列表。记事本保存黑话、详细事件、关系、待办和流程，每轮只加载全部页面目录，正文由机器人按需读取。

同一人格的群聊和私聊共享常驻资料及记事本。涉及个人事实时，写明对应成员与必要的适用会话。

## 安装和更新

适配 AstrBot 4.29.1。仓库沿用 [astrbot_plugin_self_prompt](https://github.com/littleApricot/astrbot_plugin_self_prompt)，共享源沿用 [littleApricot AstrBot 插件源](https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json)。

已发布版本可以通过插件页检查更新，或从 [GitHub Releases](https://github.com/littleApricot/astrbot_plugin_self_prompt/releases/latest) 下载 ZIP 安装。数据位于插件数据目录与 AstrBot 人格数据库，更新程序文件保留数据。

后台总结继续使用来源会话的回复模型，无需另填 API Key。回复模型需要支持工具调用；采用工具白名单的人格需加入下文列出的记事本工具、nickname_update 和 get_self_prompt。

## 用户管理页

在插件详情中打开“记忆与记事本”视图，复用 AstrBot 登录认证：

| 区域 | 操作 |
| --- | --- |
| 当前记忆 | 编辑性格和人设、回复偏好、昵称列表、其他；查看字节占用与整理进度 |
| 记事本 | 查看完整目录，新建、读取、修改和删除页面 |
| 记忆记录 | 查看当次完整资料、结果和实际原文来源；恢复选中的内容 |
| 配置 | 设置总结频率、页数上限和高级预算 |

昵称每项保存一个昵称或称呼对应关系，例如“机器人：阿蓝”“成员甲：小甲”。点“添加昵称”，编辑或删除对应行后点“保存记忆”；空行略过，相同条目去重。“其他”也可以直接编辑。

原“人格设定 → 当前人格 → 编辑 → 系统提示词”入口仍可修改常驻资料。正常保存会留下独立记录；手动编辑正文时保留已有分区定位标记。管理页保存保留外部附注。

恢复记录默认只恢复昵称与其他，保留当前人设和回复偏好；用户可以勾选同时恢复记录中的人设与回复偏好。

## 上下文和记事本

与 LCM v0.6.1 配合时，四个常驻分区通过 astrbot_plugin_self_prompt 来源进入系统块，直接显示各分区标题。完整记事本目录放入本轮临时块，每次模型调用读取最新目录，后续历史不重复保存。单独使用时，目录随本轮回复请求生成。

回复判断 v0.8.3 接收完整常驻资料、近期聊天和当前时间，不接收本轮目录或工具定义。历史里正常保留的工具调用、返回和已读正文仍按判断预算参与。正式回复使用完整的最新有效窗口。

工具使用说明随工具定义提供给正式回复模型。机器人根据目录选择页面，调用 notebook_read 读取正文；记录新事实、约定或流程时优先修改相关页，再考虑新建。

每页名称最多 24 个字符，描述最多 60 个字符，正文最多 12,000 个字符；每次最多读取 4,000 个字符，长页继续分页。目录完整展示，页数与目录字节预算同时约束新增内容。

修改和删除前先读取页面，替换正文前读完全文。页面变化时重新读取再合并；插件在当前任务内核对读取状态。满页时仍能读写、删除已有页面；降低页数上限保留现有页面，直到有空位再允许新增。

目录不反复写入历史，工具调用及返回仍沿 AstrBot 正常流程保存。已读正文随聊天窗口和压缩机制管理，页数上限不代表整个上下文大小固定。

## 自动总结与原文来源

默认每累计 100 条新消息整理一次，可修改频率。各会话与人格组合分别累计：

- 一条用户消息算一条，机器人保持沉默也计数。
- 一次最终回复算一条，工具调用、流式片段和中间输出不另计。
- 连续消息合并回复时仍按原始用户消息分别计数。
- 消息标识用于去重，重投不重复累计。

50 条用户消息加 50 次最终回复，或 100 条未获回复的用户消息，都可达到一次整理。关闭后暂停采集与开始新任务，保留队列；重新开启后继续累计，关闭期间未采集的消息不补算。

整理模型读取四个当前分区、本批新聊天以及新增或修改过的记事本页面。性格和人设、回复偏好与昵称只读，模型只返回 other 的完整新正文；人设和回复偏好是整理约束。没有新信息时返回空 updates。

只总结有明确依据、值得以后使用的简短信息，保留仍有效的旧内容。临时玩笑、推测和机器人自述不能作为用户确认的事实。黑话含义、详细事件及流程继续在记事本维护，避免将整页笔记搬进“其他”。

首次整理读取现有记事本页面，之后读取新增或改动的页面。页面名称、描述和当时正文快照随本次来源保存；页面以后修改或删除，仍可查看当次依据。页面不计入消息频率，读取进度只在保存成功后确认；失败保留来源，无变化也确认进度。

每次成功整理均保存完整四分区快照、结果“已更新”或“无变化”，以及实际读过的聊天和页面原文。聊天来源包含角色、发送人、昵称、会话、时间、文本和可取得的消息结构。图片等媒体使用文字占位形式参与整理，占位符不代表模型已识别图片。

管理页定期检查新结果并提醒，后台日志记录简短状态；这些提醒面向用户管理侧。原文独立保存在插件数据库，将旧聊天移出上下文后仍能查看。

调用失败、超时、输出不合法、跨分区写入或保存冲突时，保留待处理消息，不推进批次。原文、进度与记忆记录在插件数据库确认，跨人格数据库保存使用可恢复的待提交记录。整理期间用户或其他任务修改了内容时，后续任务基于最新内容重做。

## 配置

| 配置键 | 默认值 | 含义 |
| --- | --- | --- |
| auto_memory_enabled | true | 采集消息并自动整理“其他”；关闭后保留资料 |
| auto_memory_message_interval | 100 | 每累计多少条新消息总结一次，正整数 |
| notebook_max_pages | 100 | 每个人格当前记事本页数上限，正整数 |
| auto_memory_timeout | 60 | 单次总结调用超时秒数 |
| long_term_memory_max_bytes | 8000 | 昵称与其他内容的 UTF-8 字节上限 |
| notebook_catalog_max_bytes | 20000 | 完整目录 UTF-8 字节上限，含标识及结构 |

人设和回复偏好不计入昵称与其他的可维护内容预算，仍计入模型总输入。已有超额内容完整保留；自动总结与昵称工具产生的变化需满足预算，无变化的总结可继续留记录。

管理页分别显示正式回复常驻资料与判断常驻资料。判断优先保留完整常驻资料，剩余空间还需容纳判断指令、请求封装和近期消息；本轮目录只占正式回复的常驻资料。目录预算不能降到小于已有目录大小。

## 工具参考

所有工具绑定当前请求实际选中的人格，不接受跨人格参数。

| 工具 | 必填参数 | 可选参数 | 成功结果 |
| --- | --- | --- | --- |
| get_self_prompt | 无 | 无 | ok、sections；sections 含 persona、output_preferences、other 字符串和 nicknames 字符串列表 |
| nickname_update | 无 | add、remove，至少一个含条目 | ok、更新后的 nicknames 完整列表 |
| notebook_read | page_id | offset=0、limit=4000 | 名称、描述、正文片段及分页信息 |
| notebook_create | title、description、content | 无 | 页面标识、名称、描述、剩余容量 |
| notebook_update | page_id | title、description、content，至少提供一个 | 当前页面标识、名称、描述和容量 |
| notebook_delete | page_id | 无 | 删除结果、页数和剩余容量 |

nickname_update 的 add、remove 都是字符串列表，省略表示不操作；删除按完整条目匹配，改名可以同时删除旧项、添加新项，两者不能包含同一条目。首尾空白和重复项会去除；重复添加或删除不存在的条目保持原状。保存层限制只改昵称，对最新列表应用增删，连续冲突返回 content_changed。成功修改记录为“昵称维护”。

notebook_read 的 offset 按字符计算，limit 范围为 1 到 4000。返回 ok、page_id、title、description、content、offset、total_chars、next_offset 和 has_more；继续读取使用 next_offset。

创建的名称、描述和正文都必须非空，并符合长度限制。更新时省略的字段保留原值；提供 content 表示完整新正文，空正文会被拒绝。修改、删除前读取当前页，替换正文前分段读完；内容已变化时重新读取再合并。

失败统一返回 ok=false、error、message。昵称错误包括 invalid_nicknames、nickname_action_required、content_changed、memory_budget_exceeded；记事本错误包括 page_not_found、page_changed、read_page_first、notebook_full、catalog_budget_exceeded、invalid_page_content。

## 升级迁移与数据位置

升级前备份完整人格原文。旧固定设定内容按原文合入“性格和人设”，原人设、回复偏好保留；旧常驻 memory 内容转入“其他”。已有昵称列表沿用，旧昵称文本按非空行转换并去重。迁移不调用模型重新分类，外部附注保留，重复启动不重复合并。

已存入记事本的内容和原文来源继续保留。混在旧人设正文或笔记里的称呼保留原文，可以由用户整理，或由机器人通过昵称工具维护；自动总结只更新“其他”。

现有队列继续使用。原始备份可在记录中查看，时间标明导入时间；旧版缺失的聊天依据不伪造。旧待提交自动写入若超出新的分区权限，会标为失败并保留待整理消息。

主要数据位于 data/plugin_data/astrbot_plugin_self_prompt/：

| 位置 | 内容 |
| --- | --- |
| auto_memory.sqlite3 | 当前页面、队列、记忆记录和原文来源 |
| backups/ | 人格完整原文备份 |
| upgrade_v0_4_backup/ | 旧版升级前的队列、配置及备份 |

原文来源默认留存，记事本页数上限不限制这些资料的磁盘用量。与 LCM 配合时，旧工具管理字段在有效历史副本中隐藏，原文留在完整档案；独立运行时另存于本插件数据库，工具调用关系和业务正文保留。
