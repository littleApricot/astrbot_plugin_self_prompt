# 常驻资料与记事本计划

本计划作为当前代码的功能契约与后续验收依据。分区与权限调整随 v0.6.0 发布，功能与迁移验证尚未运行。

## 内容和权限

| 分区或资料 | 保存内容 | 加载方式 | 修改权限 |
| --- | --- | --- | --- |
| 性格和人设 persona | 身份、性格、人设要求 | 每轮完整加载 | 用户手动修改 |
| 回复偏好 output_preferences | 输出风格、格式、表达要求 | 每轮完整加载 | 用户手动修改 |
| 昵称 nicknames | 昵称、别名和称呼对应关系，字符串列表 | 每轮完整加载 | 用户编辑，机器人通过昵称工具增删 |
| 其他 other | 自动总结的简短事实、约定和提醒 | 每轮完整加载 | 用户编辑，自动总结更新 |
| 记事本目录 | 每页的标识、名称、描述 | 正式回复每轮完整加载 | 随页面变化同步 |
| 记事本正文 | 黑话、详细事件、关系、待办和流程 | 通过工具按需读取 | 用户和机器人维护 |
| 记忆记录与原文 | 四分区快照、结果和来源 | 用户打开管理页时读取 | 插件留存 |

保存层按写入来源执行精确字段限制：自动总结只允许 other 变化，昵称工具只允许 nicknames 变化；其他分区、标题和外部附注逐字保持。管理页和 AstrBot 原人格编辑入口供用户修改四个分区。模型输出校验与保存层分别检查权限。

同一人格的群聊、私聊共享资料。涉及个人事实时标明对应成员和必要的适用会话。昵称保持一个条目一个昵称或对应关系，黑话含义与详细流程保存在记事本。

## 一轮对话的数据

收到消息后，读取本轮人格的完整四分区资料，提供给回复判断和正式回复。回复判断还接收当前时间及按预算保留的近期聊天副本；正式回复使用完整的最新有效历史。

记事本完整目录放在本轮临时区。与 LCM 配合时，每次模型调用重新读取目录；单独使用时随本轮请求生成。目录不反复写入持久历史。

记事本使用说明随工具定义提供给正式回复模型。回复判断不接收本轮目录、工具说明和参数；历史里已经正常保存的工具调用、返回和已读正文继续参与预算管理。

机器人按目录选择页面，调用读取工具获得正文。工具调用与返回沿 AstrBot 原流程进入历史，已经读过且仍在窗口内的正文可以继续使用。页面变化时，写入前重新读取。

模型接口提供当前资料。管理编号、查询、恢复和存储定位信息留在插件内部与管理页；旧工具记录中的管理字段投影移除时保留原文档案及调用关系。

## 自动总结

默认每个来源会话、人格组合累计 100 条新消息触发一次，可以配置：用户消息与机器人最终回复各算一条，沉默时的用户消息也计数，工具调用和中间输出不另计。批量回复按原始用户消息计数，重投通过消息标识去重。

关闭总结时暂停新采集与开始新任务，保留队列和资料；重新开启后继续累计，关闭期间未采集的消息不补算。调节频率保留现有待处理队列，已开始的任务使用自己的消息范围快照。

整理模型读取当前四分区、本批聊天及待读取的记事本页面。首次处理现有页面，之后处理新增或改动的页面；页面不计入消息频率。模型将人设、回复偏好作为约束，昵称作为只读参考，只返回：

```json
{"updates": {"other": "其他分区更新后的完整正文"}}
```

没有新信息时返回空 updates。输出只允许 other，值必须是字符串；内容是完整新正文，需保留仍有效的旧信息。空字符串可以清空“其他”。

只记录有明确依据、值得以后使用的简短信息。临时玩笑、推测和机器人自述不能作为已确认事实；引用消息不等于当前发言者的经历。黑话与详细流程保存在记事本，避免整页复制进常驻资料。

输入过长时按顺序分段，保留实际读取的来源，不跳过旧消息。插件根据实际正文变化确定“已更新”或“无变化”，两种结果均保存当次来源并确认进度。

模型报错、超时、非法输出、跨区写入或保存冲突时，保留消息与页面读取进度，记录失败。用户或其他任务在整理期间修改内容时，后续任务使用最新正文重做。

## 保存与恢复

每次保存先留下原文备份和待提交记录，再使用 AstrBot 原生人格管理器写入、回读；成功后确认记录及批次进度。插件数据库与人格数据库不假定共用事务，重启通过原文和目标内容恢复待提交记录。

恢复尚未写入的人格变动时，自动总结和昵称工具同样接受新权限检查，不能通过旧待提交记录修改人设或回复偏好。超出权限时标为失败，保留待整理来源。已保存的原始记录继续留存。

原生人格编辑入口的正常连续保存分别形成记录。绕过保存入口的数据库修改只能在发现时留存当前状态，不承诺恢复所有中间变化。

用户恢复历史记录默认只恢复昵称和其他；同时恢复历史中的人设、回复偏好需要勾选对应选项。恢复形成一条新的用户操作记录，提交时检查当前内容是否变化。

## 工具契约

所有工具绑定本轮实际选中的人格，不接受其他人格参数。失败统一返回 ok=false、稳定 error 和 message，保存成功以工具返回为准。

### get_self_prompt

无模型入参。成功返回 ok 和 sections，sections 含 persona、output_preferences、other 三个字符串以及 nicknames 字符串列表。

### nickname_update

| 参数 | 必填 | 默认行为和含义 |
| --- | --- | --- |
| add | 否 | 要添加的字符串列表，省略表示不添加 |
| remove | 否 | 要移除的完整条目列表，省略表示不移除 |

至少一个参数含非空条目，两者不能包含同一项。条目去首尾空白、去重；删除按完整条目匹配，改名可以同时移除旧项和添加新项。重复添加已有项或删除不存在的条目保持原状。

对最新列表应用增删，连续并发冲突返回 content_changed；超过可维护内容预算返回 memory_budget_exceeded。参数无操作返回 nickname_action_required，类型不合法、空条目或管理标记返回 invalid_nicknames。成功返回 ok 和更新后的完整 nicknames，在管理页记录为“昵称维护”。同轮后续调用与下一轮可读取最新列表。

### notebook_read

| 参数 | 必填 | 默认行为和含义 |
| --- | --- | --- |
| page_id | 是 | 当前页面标识 |
| offset | 否 | 0，正文字符偏移 |
| limit | 否 | 4000，范围为 1 到 4000 |

返回 ok、page_id、title、description、content、offset、total_chars、next_offset、has_more。通过 next_offset 继续分页；分页期间页面变化时返回 page_changed，页面不存在时返回 page_not_found。

### notebook_create

| 参数 | 必填 | 含义 |
| --- | --- | --- |
| title | 是 | 非空，最多 24 个字符 |
| description | 是 | 非空，最多 60 个字符，说明页面用途和读取时机 |
| content | 是 | 非空完整正文，最多 12,000 个字符 |

成功返回 ok、page_id、title、description、remaining_pages。目录需完整展示，页数或目录字节超额分别返回 notebook_full 或 catalog_budget_exceeded。并发创建的容量检查与保存位于同一事务；同一任务重复提交相同且仍存在的页面时返回已有结果。

### notebook_update

| 参数 | 必填 | 含义 |
| --- | --- | --- |
| page_id | 是 | 当前页面标识 |
| title | 否 | 新名称，省略保留 |
| description | 否 | 新描述，省略保留 |
| content | 否 | 更新后的完整正文，省略保留 |

三个内容字段至少提供一个，长度限制与创建相同。修改前先读取，替换正文前分段读完全文，插件核对本任务读取的内容与当前页面是否一致；变化时重新读取合并。成功返回 ok、page_id、title、description。

### notebook_delete

| 参数 | 必填 | 含义 |
| --- | --- | --- |
| page_id | 是 | 要删除的当前页面 |

删除前读取当前页，内部核对内容。成功返回 ok、page_id、page_count、remaining_pages，释放当前页面容量。满页时仍能读写与删除已有页面，降低页数上限保留所有已有页，直到有空位后允许新建。

## 配置、管理与来源

| 配置键 | 默认值 | 规则 |
| --- | --- | --- |
| auto_memory_enabled | true | 控制采集及自动总结“其他” |
| auto_memory_message_interval | 100 | 正整数，按消息条数触发 |
| notebook_max_pages | 100 | 每个人格当前页数上限 |
| auto_memory_timeout | 60 | 单次模型调用超时秒数 |
| long_term_memory_max_bytes | 8000 | 昵称与其他的 UTF-8 字节上限 |
| notebook_catalog_max_bytes | 20000 | 完整目录 UTF-8 字节预算，包含名称、描述、标识和结构 |

人设、回复偏好不计入可维护内容预算，仍计入总输入。已有超额内容保留，新产生的变化需符合预算；无变化的整理仍能保留来源。目录预算不允许降到低于当前目录实际大小。

管理页复用 AstrBot 登录和插件扩展 API，提供当前记忆、记事本、记忆记录和配置四个区域。用户能手动编辑四分区、逐项管理昵称、查看字节和进度、管理页面与恢复历史。

每次成功总结留存四分区快照和实际原文来源，无变化也留记录。聊天来源保留会话、角色、发送人、昵称、时间、文本、引用与可取得的消息结构；页面来源保存当次名称、描述和正文快照。媒体按文字占位参与整理，不能将占位声明为已识别媒体。

页面读取进度只在成功保存时确认，页面在整理期间再次改变时，下次继续读取新内容。管理编号与进度不提供给模型。原文独立保存，聊天移出窗口、页面后续删除仍可追溯。

管理页定期提示总结结果，后台日志记录简短状态，不将完整聊天打印到控制台。来源时间保存为 UTC，管理展示遵循配置时区；模型输入转换为本地时间并省略时区后缀。

## 旧数据迁移

| 旧内容 | 新位置或处理 |
| --- | --- |
| 独立固定设定正文 | 原文合入性格和人设，继续仅供用户修改 |
| 原 persona、output_preferences | 分别保留为性格和人设、回复偏好 |
| 原常驻 memory | 保留在“其他” |
| 已单列的昵称 | 现有列表沿用，文本按非空行转列表并去重 |
| 已有记事本及原文来源 | 原样保留 |
| 旧纯文本人设 | 整体保留在性格和人设 |

升级前备份人格完整原文，保留外部附注，不调用模型重新分类。重复升级保持幂等。混在旧人设或笔记中的称呼保留原文，由用户整理或通过昵称工具维护。

现有待整理队列继续处理，已完成批次不重算。旧备份可导入查看并注明导入时间；旧版已缺失的来源不伪造。数据保存于 auto_memory.sqlite3、backups/ 与既有升级备份目录，更新程序文件保留这些私有数据。

## 后续验收与发布

v0.6.0 按用户要求发布，未运行测试或功能验证。后续获准时，需要在隔离临时库和管理页运行以下场景：

- 旧各类布局的原文保留、固定正文合入人设、旧 memory 转 other、重复迁移及旧笔记保留。
- 自动总结只能改 other；昵称工具只能改 nicknames，不能通过输出、标题、外部附注或恢复路径绕过。
- 消息计数、分批、无变化、来源留存、并发变动、超额预算和中断恢复。
- 管理页四分区显示、用户编辑、昵称增删去重、保存回读和选择性恢复。
- 回复判断仍看到完整常驻资料，正式回复保留最新有效窗口，工具说明和目录位置保持约定。

真实模型是否恰当使用工具和总结语义，需要单独获准的真实调用观察。发布继续使用 git、gh 和原共享插件源，版本、下载地址与校验值一并更新；发布状态与运行验证分别报告。
